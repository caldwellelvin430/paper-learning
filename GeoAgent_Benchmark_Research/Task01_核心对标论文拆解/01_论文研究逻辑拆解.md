# 从分数可信性到评价器审计

【论文事实】作者把“评价器判定是否等于真实任务成功”作为研究对象。排行榜被用于模型选择，却通常默认评价器是正确的；如果评分器拒绝合法结果或奖励未完成任务，提高 Agent 得分不能直接解释为能力进步。研究对象形式化为任务、环境与成功判据的组合 B=(T,E,G)，比较 E(τ) 与专家 H(τ)，而非训练新 Agent（§1，pp.1–2；§3.1，p.3，式1）。

## 被审计对象、样本与执行证据

【论文事实】BFCL v4（AST与模拟器状态）、τ²-Bench Retail（数据库、动作及语言断言）、LiveMCPBench 和 MCP-Atlas（LLM评分）覆盖两类评分范式，作者称其有代表性（§3.2；§4.1，pp.3、6）。τ²采用 Kimi-K2.6，其余三者采用 MiniMax-M2.7；不是四基准上同一模型的能力对照。没有给出候选全集、随机抽样概率、纳入排除流程或分层权重，因此无法把分歧率无偏外推到所有工具调用 Benchmark。

Harness Lab 启动基准原有 runner，保留请求、调用、输出、最终回复、官方标签、评价日志及可获得状态，记录版本、补丁、数据和端点配置。运行在 Google Cloud us-central1，模型通过兼容 OpenAI 的 HTTP 端点访问（§3.9、§4.1，pp.5–7）。这是一套证据采集链，不能据此认为所有任务都获得了完全可观测的环境真值。

## 独立成功判据与错误认定

【论文事实】三名独立专家查看完整轨迹、工具结果、状态变化和用户可见结果，以用户目标是否达成为 PASS/FAIL 判据，再裁决分歧；报告89标注工时、约10.8分钟/任务。官方 y=0、专家 h=1 为假阴性；y=1、h=0 为假阳性（§3.3，p.3；§4.1，p.6，式2、5、6）。

【分析】专家标签提供相对独立的参照，但“以用户目标为准”尚不是充分可复制的操作手册：盲审、专家资历、裁决前一致率和任务歧义处理均未充分报告。因此应称“相对专家判断的分歧”，不能不加限定地称客观错误。

案例证据最完整的是 τ² Task 7：取消指定预约后，两项剩余预约金额402与306，合计708；官方语言断言要求1628，尽管状态和五个动作匹配仍判失败。Task 10 未调用退货工具而转人工，数据库未变却获通过（§4.3，pp.7–8；附录A.1，p.11，表6）。从用户意图重算结果及检查未执行动作，比直接采用官方参考答案更有说服力。

## 从原因归纳到评价设计

【论文事实】§3.4按轨迹和评价器检查进行多标签归因。§3.6提出工具调用、任务完成、结果验证三分量 c=(Ctool,Ctask,Coutcome)，不是三个已有数值指标的完整计算规范。§3.7宣称修正标注、评分逻辑和运行管线，但没有提供同一批轨迹修正前后的逐项结果表。Tool-Veritas以状态谓词验证事实，定性Judge不能推翻硬门失败，保留修复前后状态；Harness Lab保存和调试证据（§3.6–3.9，pp.4–6）。

| 贡献 | 实验／实现支撑 | 支撑边界 |
| --- | --- | --- |
| 496条轨迹有效性审计 | 表3，92分歧 | 不是所有任务总体的随机估计 |
| 失败分类体系 | §4.3、附录A、BFCL诊断与τ²案例 | 无逐类型完整计数；部分类型仅作概述 |
| 分解式评价框架 | §3.6及Tool-Veritas架构 | 无三分量独立消融 |
| Tool-Veritas | 表5，401/420一致 | 不同任务和模型配置，非旧评分器的配对修复实验 |
| Harness Lab | 表2与公开实现 | 功能与可追溯性支撑，无独立用户效率评估 |

【迁移建议】借鉴的是先建立独立判据、查分歧、定位根因、再修评价器的顺序。只有发现实际地学失效证据后，才能确定需要改造哪一种评分机制。
