# GeoAgent Benchmark 研究文献分类与优先级规范

> 版本：v1.0｜2026-11-24
> 用途：新增文献入库前的分类、命名、优先级判断与阅读安排。适用于 paper-learning 仓库及后续 ChatGPT / Codex 对话。

## 1. 研究背景与分类目的

当前研究方向：**以系统性综述为基础的地学 Agent Benchmark 有效性审计与评价方法研究**。

核心对标论文：*Benchmarking the Benchmarks: A Validity Audit of Tool-Calling Evaluation*。

研究主线：梳理现有地学 Benchmark 与评价指标 → 实证审计评价机制 → 归纳失败原因 → 根据证据提出改进指标或评价框架 → 在已有 Benchmark 中验证 → 为不同类型的 GeoAgent 提供 Benchmark 选择建议。

分类的首要依据是**论文在本研究中的用途**，而非年份、发表等级、引用量或标题中是否出现 Geo、Agent、Benchmark 等词。文献分类不是 Benchmark 质量排名，也不代表已经完成实证核验。

## 2. 七个主类别

| 类别 | 名称 | 核心判断标准 | 默认阅读优先级 |
|---|---|---|---|
| A | 核心地学 Benchmark | 直接评价地学工具调用、多步骤规划、工作流执行或空间结果，具有较高审计价值 | P0–P1 |
| B | Benchmark 审计与方法论 | 研究评价机制本身是否有效、可靠、可复现，或提出评价器验证、基准审计、质量评价方法 | P0–P1 |
| C | 地学专项 Agent Benchmark | 面向遥感、灾害、气候、天气等专项任务的 Agent 评测，能够补充研究范围或验证方法泛化 | P1–P2 |
| D | 地学知识、感知与代码评测 | 主要评价静态问答、视觉理解、领域知识或独立代码生成，而非动态多步骤 Agent 执行 | P2，可提升 |
| E | 通用 Agent Benchmark 与评分机制 | 非地学的 Agent 或代码任务基准，主要用于借鉴具体评分机制、GT、执行测试或环境设计 | P1–P2 |
| F | 地学 Agent 系统与综述 | 主要贡献为 Agent 架构、应用系统、领域综述或概念框架，未以可独立研究的基准为主要贡献 | P2–P3 |
| G | AI 与 Agent 基础文献 | 通用模型、Agent 架构、规划、感知工具等基础方法，与 Benchmark 评价研究关联较间接 | P3 |

### A｜核心地学 Benchmark

**纳入标准：** 论文提出或实质性研究地学任务基准，且主要评价对象涉及工具选择、参数与数据语义、多步骤规划、实际执行、空间输出等至少一个关键环节，并与当前研究的指标比较或有效性审计直接相关。

优先关注：GT 类型、参考轨迹、真实输出、评价器规则、替代正确路径、空间语义约束、评分粒度。缺少开源数据不自动排除 A 类，但要单独降低实验可行性评级。仅考察规划的基准可以纳入，但必须标记其未验证真实执行。

现有例子：GeoAgentBench、GISAgentBench、GeoNatureAgent、GeoContra、GeoBenchX、GeoAnalystBench、ThinkGeo、HTAM_EarthAgent（GeoPlan-bench）、GeoLLM-Engine。

### B｜Benchmark 审计与方法论

**纳入标准：** 将 Benchmark、评价指标、裁判模型、GT 或评价器的有效性作为主要研究对象，或提出可用于这些问题的元评价方法。

优先关注：构念效度、任务效度与结果效度、评价失败分类、专家复核、故障注入、已知答案对照、裁判一致性、重复评分稳定性、基准质量标准及选择建议。

现有例子：Benchmarking the Benchmarks、AgentSuite、Oracle Failures、Measuring What Matters、Beyond the Final Answer、BetterBench、ABC、AgentJudgeBench、Fantastic Bugs。

**区别于 E 类：** B 类主要回答“评价器或 Benchmark 是否值得信任、如何验证”；E 类主要回答“如何评价 Agent 的能力”。

### C｜地学专项 Agent Benchmark

**纳入标准：** 具有独立任务与评价机制，但应用领域相对专门，例如地球观测、灾害应急、气候分析、天气科学等。

优先关注：是否具有可执行轨迹、独立 GT、空间产物及可迁移的评分机制；是否能补充 A 类缺少的任务类型。

现有例子：DORA、EarthVerse、Earth-Agent（Earth-Bench）、Earth-Agent-Pro（Earth-Bench-Pro）、EO-Gym、GeoDisaster、OpenEarthAgent、TerraLogic、UnivEARTH、ClimateAgent、Zephyrus。

**提升规则：** 若专项基准的评价机制与核心问题高度相关，并具有明确的审计价值，可提升至 A 类。是否开源、能否本地执行另行记录，不将其与学术相关性混为一谈。DORA、EarthVerse 是优先考虑提升的候选。

### D｜地学知识、感知与代码评测

**纳入标准：** 主要衡量地学知识、图像理解、静态空间推理、科学问答或独立代码生成能力，即使使用了 Agent 作为基线，也未必评价完整 Agent 执行过程。

优先关注：领域能力划分、科学证据依赖性、代码测试、结果正确性验证。若基准真正评价多步骤工具执行和环境交互，应重新考虑 A/C 类。

现有例子：Evaluation of Code LLMs on Geospatial Code Generation、GeoCode-GPT（GeoCode-Eval）、EarthSE、GEOBench-VLM、GeoMMBench_GeoMMAgent、MSEarth。

### E｜通用 Agent Benchmark 与评分机制

**纳入标准：** 非地学领域的工具调用、软件工程、数据科学或多轮 Agent 评价基准，主要研究 Agent 表现，但其评分方法具有可借鉴性。

优先关注：状态匹配、里程碑、部分得分、功能测试、语义等价、执行成功率、重复试验指标及跨环境评价。

现有例子：ToolSandbox、AgentBoard、tau-bench、DS-1000、SWE-bench、API-Bank。

### F｜地学 Agent 系统与综述

**纳入标准：** 主要贡献为地学 Agent 系统、工具编排、应用实践或综述；论文可能使用 Benchmark 进行实验，但其本身不一定提出独立基准。

优先关注：地学 Agent 的能力分类、应用需求、系统架构和研究背景。若系统论文同时提出有独立任务集、GT 和评价协议且与研究高度相关的 Benchmark，可纳入 A/C，附加“Agent 系统”标签。

现有例子：Autonomous GIS、GIS-Copilot、MapAgent、AgenticAI_Survey、GeoAgent（地址标准化）。

### G｜AI 与 Agent 基础文献

**纳入标准：** 通用模型或 Agent 基础技术，主要用于理解技术背景，不直接提供本研究的地学评测对象或评价审计方法。

现有例子：ReAct、Plan-and-Solve、Voyager、Generative Agents、Attention Is All You Need、Segment Anything。

## 3. 新文献分类判定流程

先读摘要、贡献、任务定义、Evaluation/Metrics、实验和局限；对于 A/B/C 类候选，进一步检查英文原文及可获得的评价代码。不要仅凭标题或中文译述作最终判定。

按主要研究贡献依次判断：

1. 论文是否直接研究 Benchmark 或评价器自身的有效性、可靠性、缺陷、质量、元评价？若是，优先 B；若主要贡献是新的地学执行基准而兼具验证方法，归 A/C，并附 B 类方法标签。
2. 是否提出或实质性分析一个可识别的地学 Agent Benchmark？若是，检查是否涉及多步骤规划、工具调用、环境交互或结果验证。直接服务于本研究核心问题归 A；主要服务于专项领域与泛化验证归 C。
3. 是否主要是地学静态问答、感知、知识、独立代码生成评测？若是，归 D。
4. 是否主要提出非地学的 Agent/代码 Benchmark 或具体评分机制？若是，归 E。
5. 是否主要是地学 Agent 系统、架构、应用或综述？若是，归 F。
6. 是否主要为通用 AI/Agent 基础技术？若是，归 G。
7. 证据不足时标记 `待分类`（临时状态，不是第八个正式类别），补读后再确定。

**一篇论文一个主类别，允许多个辅助标签。** 主类别依据论文对本研究的主要作用确定；如果存在冲突，记录选择理由及次要作用，不重复计数。分类可随研究进展修订。

## 4. 阅读优先级：P0–P3

| 优先级 | 判断标准 | 阅读要求 |
|---|---|---|
| P0 | 直接影响核心研究问题、实证审计对象选择或关键方法设计；或属于必须区分创新性的直接相关工作 | 精读原文方法、指标、公式、实验、局限与附录；必要时核对代码 |
| P1 | 可补充评价机制、审计方法、研究对象或跨 Benchmark 验证 | 针对性精读有关章节，记录可复用方法与证据 |
| P2 | 主要支持相关工作、研究边界、补充指标或专项背景 | 阅读摘要、评价部分与结论，按需深读 |
| P3 | 基础背景或与当前研究关联较弱 | 归档，必要时查询 |

### 优先级判断维度

- 研究相关性：是否直接回答评价指标测量了什么、评分是否可信、怎样改进或如何选择 Benchmark？
- 方法可迁移性：是否提供可操作的审计、评分或验证方法？
- 评价机制独特性：是否能补充已有文献覆盖不到的 GT、轨迹、空间约束或结果验证方式？
- 创新性约束：是否与拟议方法高度重合，必须提前明确区别？
- 实证支持价值：是否能支持受控对照实验或提供有价值的失败样本？

不必机械计算综合分。满足核心对标或直接相关工作的条件即可标 P0；其他根据证据综合判断并用一句话说明理由。

**阅读优先级不等于实验优先级。** 例如 GISAgentBench 可以是 P0，即使其完整数据或评价器暂时无法获取；开源且容易运行的论文也不必自动成为 P0。

## 5. 实证审计可行性（独立字段）

仅对有实证审计价值的 Benchmark 记录，方法论或基础论文可填 `N/A`。

| 等级 | 定义 |
|---|---|
| R0 | 已验证任务、GT、评价器和必要环境可获取，能开展小规模真实评分或重放，并能取得独立核验所需证据 |
| R1 | 主要材料可获取，但环境、依赖、轨迹或独立核验条件仍需补齐或实际测试 |
| R2 | 部分核心材料不可获取，暂只能做文献分析或有限实验 |
| RU | 尚未核查，不能判断 |
| N/A | 非本研究的实证审计对象 |

分项检查：任务集、GT、参考轨迹、输出产物、评价器源码、执行环境、API 依赖、固定轨迹重复评分条件、构造对照样本条件、独立人工核验条件。

开源状态分别记录：作者声称公开 / 提供链接 / 实际可访问 / 已下载 / 已验证运行。论文中的链接不能直接证明复现成功。

## 6. 辅助标签（按需选择）

| 标签组 | 推荐标签 |
|---|---|
| 研究用途 | 核心对标、直接审计对象、方法借鉴、创新性对照、选择指南、相关工作 |
| 评价对象 | 工具选择、参数正确性、数据语义、规划路径、工作流执行、过程完成度、最终结果、空间语义、证据一致性、效率与成本 |
| 评价机制 | 确定性规则、LLM Judge、VLM Judge、轨迹匹配、代码相似度、可执行测试、状态验证、部分得分、空间容差、人工审计 |
| GT 类型 | 标准答案、参考代码、参考轨迹、真实空间产物、状态约束、任务专用 rubric、独立专家判据 |
| 方法论 | 构念效度、元评价、评价器故障注入、评分稳定性、缺陷分类、跨 Benchmark 验证、基准质量审计 |
| 任务领域 | GIS、遥感、地球观测、灾害、气候、天气、地图服务、空间推理、通用工具调用、代码生成 |

标签应以论文实际内容为依据；不明确的字段填 `待核验`，不把作者声称的能力直接当作已验证能力。明确区分作者报告的缺陷、独立实验发现的缺陷和待检验的研究假设。

## 7. 新文献入库记录模板

每次上传新论文前，使用以下模板记录分类结果。允许在未取得全文时生成临时分类，但须注明证据范围。

```yaml
paper_title: "完整英文标题"
paper_short_name: "仓库短名称"
benchmark_name: "实际 Benchmark 名称；没有则 N/A"
year: "年份或待核验"
publication: "会议/期刊/预印本及版本；待核验也可"
source_url: "DOI / arXiv / 正式出版页面"
primary_category: "A/B/C/D/E/F/G 或待分类"
reading_priority: "P0/P1/P2/P3"
research_role: ["直接审计对象", "方法借鉴"]
secondary_tags: ["轨迹匹配", "空间语义"]
classification_reason: "一句话说明主要贡献与本研究的关系"
measurement_target: "实际测量对象"
evaluation_mechanism: "评价器及主要指标；未知则待核验"
ground_truth_type: "GT 类型；未知则待核验"
reproducibility: "R0/R1/R2/RU/N/A"
open_source_status: "代码、数据、评价器分别注明状态"
evidence_location: "摘要 / 第 X 节 / PDF 第 X 页 / 源码路径"
verification_status: "暂定（仅摘要）/ 原文核验 / 代码核验 / 实验核验"
reading_focus: "最值得阅读的章节或需要回答的研究问题"
local_path: "论文翻译/论文短名称/"
```

建议保持原始论文目录和配图相对路径，分类通过 `GeoAgent_Benchmark_Research/` 下对应类别 README 的链接及文献总索引维护；不需要复制或移动整套 PDF、图片和译稿。新增论文时同步更新索引及分类导航，避免重复收录同一论文不同版本。

## 8. 给 ChatGPT / Codex 的新增文献分类提示词

```text
请依据《GeoAgent_文献分类与优先级规范.md》，对我本次上传的所有新论文逐篇分类。

我的研究方向是地学 Agent Benchmark 评价指标梳理、评价有效性审计、改进评价方法和 Benchmark 选择建议。核心对标论文为 Benchmarking the Benchmarks: A Validity Audit of Tool-Calling Evaluation。

请阅读每篇论文的摘要、主要贡献、任务定义、评价指标、实验与局限，必要时核查英文原文。不要只根据标题判断。

对每篇论文输出：完整标题、实际 Benchmark 名称（没有则 N/A）、主类别（A–G）、阅读优先级（P0–P3）、分类理由、研究用途、辅助标签、主要测量对象及评价机制、GT 类型、实证审计可行性（R0/R1/R2/RU/N/A）、证据位置与重点阅读章节。

优先区分：核心地学 Benchmark、Benchmark 审计方法、专项地学 Agent Benchmark、静态地学评测、通用评分机制、地学 Agent 系统和基础文献。

分类必须唯一，但辅助标签可以重叠。阅读价值与实验可行性独立判断。无法核实的信息标记待核验，不编造指标、GT 或开源状态。如果新论文明显更适合核心研究对象，请说明提升优先级的依据。

最后输出一张简洁分类表，以及每篇论文可直接加入文献索引的 YAML 记录。若发现与已有论文重复或同名不同系统，请指出。仅做分类，不修改原论文文件，不开展大规模复现实验，不自动 git push。
```

## 9. 维护原则

本规范用于保持文献库长期一致，不用于提前限定研究结果。若实际阅读发现某个类别或标签不适用，可以调整并记录理由。每次新增文献重点确认它能帮助回答什么研究问题，而不是单纯扩大文献数量。
