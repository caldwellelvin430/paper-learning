## 摘要（完整翻译）

地球观测（Earth Observation，EO）分析本质上是一个交互过程：为了降低不确定性，分析者往往需要扩大感兴趣区、获取历史观测，并在光学与合成孔径雷达（SAR）等传感器之间切换。然而，多数现有地球观测基准将这一过程简化为输入固定、单轮作答的任务。针对这一局限，本文提出 **EO-Gym**，一个面向多模态、工具使用型地球观测智能体的受控可执行框架。EO-Gym 将地球观测分析建模为 Gymnasium 风格的本地地理空间工作区，底层包含按位置、时间和传感器类型索引的 **66 万余个多模态文件**，并提供覆盖六类任务的 **35 种专业 EO 工具**。

基于该环境，作者构建了 **EO-GYM-DATA**：包含 **9,078 条轨迹与 34,604 个推理步骤**，使用八个公开 EO 数据集及 Landsat、Sentinel-2 影像。对 10 个开源和闭源视觉语言模型（VLM）的测试发现，即使能力较强的通用模型，在时间维度与跨模态交互工作流中仍面临显著困难。作者进一步在 Qwen3-VL-4B-Instruct 上微调得到 **EO-GYM-4B**；在主评价设置下，整体 **Pass@3 从 0.49 提升至 0.74**。EO-Gym 通过可复现的可执行环境，将 EO 分析明确表述为需要跨空间、时间和传感器模态规划的证据获取问题。

## 1. 引言：从静态遥感图像问答走向交互证据获取

常见 EO 问题难以仅凭一张初始图像解决。对目标是否发生变化的判断可能需要调取历史影像；由于云层遮挡而无法使用光学数据时，可能必须转向 SAR；当图像范围过小时，可能需要平移、缩放、获取邻接瓦片并重新观察。传统评测更强调对固定输入作出回答，而缺少对模型主动搜集证据的状态序列进行评价的统一环境。

本文把这一过程称为**交互式证据获取（interactive evidence acquisition）**：智能体必须根据当前观察结果决定下一次数据访问动作，在位置、时间和模态之间转换，并将后续观察用于修正结论。评价重点因而包括动作是否合法、工具调用是否高效、是否发现适当证据，以及最后答案是否正确。

## 2. 相关工作

通用 Agent 基准（如 ToolBench、GAIA、GTA、WebArena、OSWorld）验证了可执行交互环境的重要性，但通常不涉及地球观测对时空索引和传感器模态的依赖。现有 EO 视觉数据集（如 xView、DOTA、DIOR、FAIR1M、SARDet、VRSBench）侧重分类、检测或固定输入的视觉理解。ThinkGeo、Earth-Bench、OpenEarthAgent 等将工具调用引入遥感任务，却没有提供同时支持**空间扩展、历史时相获取、光学与 SAR 动态切换**的统一、受控 VLM 环境。EO-Gym 的主要差异是将环境状态和数据访问过程正式作为研究对象。

## 3. 可执行 EO-Gym 环境

### 3.1 本地多模态数据湖

EO-Gym 根据地理位置、时间戳、数据源和传感器类型组织超过 **660,000 个文件**。资料来自八个公开数据集，并融合不同卫星及数据任务（例如 FAIR1M 地理定位、xBD 灾害评估、fMoW 时序信息、M4-SAR 跨模态识别）。本地查找能够避免远程 API 变化导致的环境漂移，保持评测可复现。

### 3.2 三种核心数据获取动作

- **Spatial Planning（空间规划）**：平移或缩放图像，访问初始视窗之外的地理区域。
- **Temporal Fetching（时相检索）**：针对同一地理位置获取历史影像，用于变化发现和时间比较。
- **Cross-Modal Switching（跨模态切换）**：借助一致的地理空间定位，在光学、SAR 及相关观测之间切换。

系统共有 35 种 EO 工具，返回的可能是影像裁块、JSON 边界框、掩膜、NDVI、NDWI 等派生指数或其他结构化观测。模型在观察、行动与中间计算之间循环，直到能够回答问题或达到执行预算。

### 3.3 三轴实验配置

论文为隔离不同能力而设计三个实验维度：

1. **Verified / Unverified 观测模式**：Verified 利用真实值辅助模拟器或校验机制，提高感知工具输出的可控性；Unverified 返回原始工具结果，用于考察感知误差在整个工作流中的传播。因此 Verified 的高分不等于真实部署场景下的端到端鲁棒性。
2. **Simple / Detailed 提示**：Simple 仅要求模型通过工具获取证据；Detailed 提供时空与模态访问的一般建议，但不直接泄露目标工具名称或参数。
3. **Skill / All 工具集**：Skill 仅暴露相关任务工具；All 则展示全部 35 种工具，以模拟开放工具环境。减少工具候选集能显著改变任务难度，故跨 Benchmark 比较时必须固定这项配置。

## 4. EO-GYM-DATA：轨迹数据集

### 4.1 数据构成与质量控制

EO-GYM-DATA 包含 **9,078 条可用交互轨迹、34,604 个推理步骤、6 类主要 EO 任务和 18 类问题形式**。作者划分出 **7,642 条训练轨迹**和 **1,436 条人工核验测试轨迹**，并通过来源影像及问题类型隔离、文件名哈希掩码等手段降低信息泄漏风险。图 2 展示了任务类别、地理分布、时间跨度和轨迹长度等统计。

### 4.2 候选问题、生成与审查

作者从公开数据集标注构建候选问答，以多项选择格式引导轨迹合成，再通过真实执行获取动态数量的答案。GPT-4.1 在 Verified、Detailed、Skill 环境中进行最多 50 次函数调用，生成工具交互轨迹；随后由审查模型检查中间动作、证据与结果的一致性，并在错误时反馈给生成器开展修复。最多进行三轮生成—审查循环。最终对于测试集由人工严格校验，对训练集使用模型结合人工提炼的规则进行审查。正式评测以自然语言答案形式呈现，从而避免多项选择格式带来的猜测偏差。

### 4.3 数据集的可复用性

任务轨迹既可用于模型训练，也可作为评测中的参考过程。与静态问答不同，轨迹保存了交互动作与观测序列，可以分析工具滥用、过早作答、错误模态选择、缺失历史影像以及重复调用。数据集是否可靠仍依赖人工复核质量、模拟器的 Verified 假设和训练—测试隔离方式。

## 5. 模型训练与评价协议

### 5.1 EO-GYM-4B 训练

作者以 **Qwen3-VL-4B-Instruct** 为基础，通过低秩适配微调（LoRA）学习 EO-GYM-DATA 中的交互轨迹，获得 EO-GYM-4B。训练目标不仅是给出正确答案，还包括何时调用工具、如何切换证据以及如何遵循 EO 环境的接口约束。

### 5.2 主要指标：Pass@k、工具行为与错误率

**Pass@k** 表示在 k 次候选尝试中至少存在一次正确回答的概率，是本文主要最终答案指标。对每题采样 n 次，其中 c 次成功时，原文采用 `1 − C(n−c,k)/C(n,k)` 形式的无偏估计，再在任务间取均值，并通过 Bootstrap 给出置信区间。该指标依赖采样预算，不能与单次任务准确率直接混用。

论文还报告：**Tool-call ratio**（消费轨迹的实际工具调用量与参考调用量之比）、**Illegal error rate**（已消费调用中返回空、缺失或执行错误的比例）、**Tool-any**（不考虑顺序时，实际调用工具集合覆盖全部参考工具的任务比例）。附录进一步给出精确工具序列匹配等指标。最终答案与轨迹指标是互补的：相同正确答案可能通过冗余或错误过程获得，参考轨迹相似也不保证模型识别出的证据具有科学有效性。

## 6. 实验与消融研究

### 6.1 主要结果

在 Verified / Skill / Simple 主设置下，EO-GYM-4B 的 **Pass@1=0.65，Pass@2=0.71，Pass@3=0.74**，均领先其基础模型；基础 Qwen3-VL-4B-Instruct 的 Pass@3 为 **0.49**。模型不只是答对率更高，其工具使用覆盖度与执行效率也获得改善。这表明基于真实交互轨迹进行领域微调有助于模型掌握 EO 工作环境中的操作规律。

### 6.2 稳定性、配置敏感性与工具迁移

作者测试更大重复采样预算、Detailed Prompt、Unverified 模式和 All Tools 模式。高 Pass@k 并不一定意味着一次尝试就能稳定成功，因此追加 Self-Consistency（答案多数一致性）等诊断。面向工具迁移，作者还检查模型在新工具组合及工具名称改写情况下是否仍可操作，避免将“背过工具名”误判为对功能的真正理解。

### 6.3 传感器与数据泄漏诊断

论文使用多光谱测试子集分析训练数据泄漏风险。原文附录表明，通用模型在该子集上的准确率显著下降，而 EO-GYM-4B 仍保留明显优势。作者还设计时相访问工具的训练—测试隔离：训练轨迹使用光学时序工具，测试轨迹使用多光谱时序工具，借此检查跨工具与跨模态迁移。但对于空间规划任务，论文也明确说明其设置更接近问题形式迁移，而不是严格工具名称完全隔离；这一点在解释泛化结论时应保留。

### 6.4 Verified 模式可能掩盖的错误

在 Unverified 模式下，实际感知工具可能错误识别建筑数量、给出有噪声的边界框或遗漏精确历史影像；这些中间观测异常会导致最后的灾损比例、地物判断或时间回答错误。原文表 28 给出多个对照案例，提示**工具调用成功**与**感知输出正确**是两回事。对于地学 Agent 的可靠性评测，推荐把工具执行状态、观测质量、空间证据有效性与最后答案分开报告。

## 7. 结论与未来工作

EO-Gym 提供一个可复现、具有状态的多模态 EO 工具环境，EO-GYM-DATA 提供规模化交互轨迹，EO-GYM-4B 展示了用轨迹数据微调来提高证据获取行为的可行性。论文的关键观点是：地球观测不应被简单当成“看图回答问题”，而应评价系统如何主动选取空间、时间和传感器证据。

作者同时讨论了环境规模、模拟观测的逼真程度、模型与工具的泛化以及真实部署约束；基准中的 Verified/Skill 设置本身是为了隔离不同能力，不应视为所有实际 EO 工作流天然具有的条件。

## 对 Benchmark 指标设计的启示

EO-Gym 的优势是评测**可执行交互环境**，并将 Pass@k、工具集合覆盖、精确调用匹配、无效工具执行和调用效率并列报告。其弱点或至少需要额外审计的条件包括：Verified 模式对上游感知误差的屏蔽、Skill 模式对工具选择难度的削减、评审模型判断的偏差，以及参考轨迹对可替代有效路径的容忍度。进行跨 Benchmark 比较时，应先核对每个系统是否获得同等输入信息、相同工具集、相同执行预算与同样的正确性定义。
