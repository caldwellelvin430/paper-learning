Two things are deliberately not distributed. The second, independently imple-
mented agent framework used for the portability result ships its task data under a
licence that permits redistribution only in encrypted form, so the package carries
the adapter, the applicability ﬁndings and the version ﬁngerprint, and this paper
reports no detection rate for it. The model-served episode records are distributed
as frozen records; they contain outputs of third-party model services and are not
oﬀered under an unconditional open licence.
The code authored for this study is released under the MIT licence. The frozen
records are not covered by that licence and carry their own terms, stated in the
package: the derived results and the per-episode records may be used and redis-
tributed for research with attribution, while large-scale redistribution or commercial
use of the episode records should be requested ﬁrst, because they contain outputs
of third-party model services.
Note on byte-reproducibility: the analyses are deterministic and recomputable from
the frozen records, but the PDF is not byte-reproducible, because the LATEX engine
writes a build timestamp and a document identiﬁer into every ﬁle it produces. The
published PDF should therefore be bound to the released source by a hash of the
source, not of the PDF.
• Code availability. The analysis and experiment code is contained in the archives
above and is also available at https://github.com/JunjieChen0/SimGlot (tag
v1.0.0). Three entry points drive every oﬄine analysis: one for the S2 side, one
for the enhancement side, and one for the v1.0 analyses. The oracle-integrity suite
runs from a single command and needs no network, no credentials and no model;
it audits the benchmark’s own oracle and prints the defect-class × detector matrix
reported in Table 3. The end-to-end analysis is reproducible from the archived
episodes by one further command that neither reads an API key nor opens a net-
work connection, and that refuses to run if a key is present in the environment,
so that a claimed oﬄine reproduction cannot silently become an online one. The
suite’s interface is four operations wide, so it can be pointed at another harness’s
oracle without changing the suite itself.
• Use of large language models. Language models are the experimental material
of this study: they act as the tool-calling agents under test, as the user simulators
that generate the test inputs, as the translator that produced the Chinese task
instructions (with the mechanical ﬁdelity check described in Section 3.3), and as
the independent adjudicator in Section 4.3. The models are speciﬁed by name and
version throughout, and the prompts given to the adjudicator and to the translator
are released with the package. Language models were also used to assist in drafting
the manuscript and the analysis code; the author reviewed and is responsible for
all content, analyses and conclusions.
