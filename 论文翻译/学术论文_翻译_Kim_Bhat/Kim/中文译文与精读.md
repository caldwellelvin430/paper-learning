## 摘要

尽管近期工具增强型智能体基准包含越来越复杂的请求，但评价仍主要局限于最终答案匹配，忽略了效率、幻觉和适应性等关键的轨迹属性。最直接的轨迹评估方法是将智能体轨迹与标准轨迹比较，但为同一问题标注所有可能正确的标准轨迹成本极高。针对这一问题，作者提出 **TRACE**，一种不依赖预先定义的单一路径参考答案的多维工具增强型大语言模型评价框架。TRACE 使用一个持续收集先前步骤知识的**证据库（evidence bank）**，对智能体的推理轨迹进行评估。为检验这一框架，研究构建新的元评价（meta-evaluation）数据集，包含多样且存在刻意缺陷的轨迹，并为其提供多维评价标签。实验表明，即使使用较小的开源大语言模型，TRACE 也能有效评价复杂轨迹。进一步将 TRACE 应用于真实工具增强智能体的轨迹后，作者发现了过去仅依据最终准确率而被掩盖的能力差异，并讨论了其对智能体改进的启示。

## 1 引言

随着大语言模型（LLM）的持续进步，能够借助外部工具突破自身能力限制的工具增强型智能体获得广泛关注。相应的基准测试也不断出现，用于衡量智能体解决任务的能力。然而，已有评估大量关注智能体**完成了什么任务**，却很少深入检查智能体**通过什么过程完成任务**。

现有基准主要采用答案匹配（Answer Match），即核对最终输出是否与标准答案一致。作者认为，即便两个模型取得相同的准确率，其能力也未必相同：一个智能体可能只需少量步骤就找到答案，另一个则可能反复调用无关工具、产生幻觉，或者无法在工具不可用时调整策略。合格的智能体不仅应得到正确答案，还应高效完成推理，避免凭空推断，并在工具失效时尝试合理的替代工具。

图 1 提供一个直观例子：两个智能体面对同一个“根据菜单计算桌上啤酒总价”的任务，最后都回答 12。第一个智能体在工具 `FastCalculator` 不可用时改用 `Calculator`，体现适应性；第二个智能体对水瓶执行不必要的计数，还臆测啤酒品牌，从而暴露低效与幻觉。如果只记录最终答案，两者会被认为等价；观察过程才能揭示差异。

人工评估推理过程往往准确，但随着轨迹长度和复杂度增加，成本难以接受。单纯使用 LLM 将模型轨迹与一条标准轨迹匹配也存在结构性问题：同一个请求可以由多条同样有效的工具链解决，不应将与单条标准路径不同的有效方案判错；但枚举所有正确路径并不可行。此外，简单的 LLM 裁判在长而复杂的上下文中也可能能力下降。

因此，作者提出 TRACE，通过逐步积累可核查的工具执行证据，在不依赖预先标注的唯一标准轨迹的情况下评价整个问题解决过程。其三项关键指标为：

- **效率（Efficiency）**：是否执行了对最终答案无帮助的冗余步骤。
- **幻觉（Hallucination）**：推理中的事实性陈述能否由已收集的证据支持。
- **适应性（Adaptivity）**：面对不可用或失效工具，是否能够合理更换工具或调整策略。

为检验评价器本身，论文在 GTA 和 m&m’s 两个既有工具智能体基准上构建扩展数据，添加多条合法轨迹及刻意注入的错误，并为冗余步骤、幻觉及适应性行为赋予标签。结果显示，TRACE 能够识别这些细节，而且允许使用成本较低的开源模型作为裁判。作者进一步发现，传统排行榜上性能接近的智能体，其轨迹质量可能很不相同。

原论文所总结的贡献包括：（1）一个不依赖单一标准路径、可用小模型进行过程评估的轨迹评价框架；（2）效率、幻觉与适应性的多维评价方法；（3）对当前工具增强智能体的过程行为与失败机制进行实证分析，进而提出能力改进方向。

## 2 相关研究

LLM 使用外部工具的能力建立在思维链（Chain-of-Thought, CoT）和 ReAct 等基础技术之上。ReAct 通过将“思考”与“动作”交替执行，使智能体可以持续根据工具返回调整策略。ToolLLM 可覆盖大量 API，TORA、MMedAgent 和多模态智能体则在数学、医学、视觉等专业任务中拓展了工具使用的范围。

GAIA 等基准评估一般助理解决真实问题的能力，MetaTool 关注“是否应该使用工具、应该使用哪种工具”。但许多基准仍主要看最终答案，或与 GTA、m&m’s 一样依赖单个预定义参考路径。此做法一方面可能惩罚有效的替代方案，另一方面不便随工具和任务复杂度扩展。

近来一些研究开始关注过程评价，例如 ToolBEHonest 研究工具增强型模型的幻觉，PIPA 关注交互规划智能体的状态一致性。然而，仅评估单个行为维度并不足以描述完整推理过程，多个正确路径之间产生的评分差异仍是难点。TRACE 试图从多维度对轨迹本身进行评估，兼顾可解释性和参考路径无关性。

## 3 提出的方法

### 3.1 工具增强型智能体轨迹的形式化

给定用户问题 \(Q\)，智能体通过外部工具交互形成按顺序排列的轨迹：

\[
T=(s_1,s_2,\ldots,s_n),
\]

其中 \(s_n\) 为产生最终回答 \(Ans_{final}\) 的结束步骤。对于 \(t\in[1,n-1]\)，ReAct 轨迹中的每步定义为四元组：

\[
s_t=(th_t,a_t,i_t,o_t).
\]

- \(th_t\)：智能体生成的思考（thought），用于解释当前状态与下一步决策。
- \(a_t\)：动作（action），即从可用工具集合 \(A\) 中选择的工具。
- \(i_t\)：动作输入（action input），包括所选工具的参数或实参。
- \(o_t\)：观察结果（observation），即工具用这些参数执行后返回的结果，也是下一步推理的上下文。

最后一步 \(s_n\) 输出依据先前步骤得到的最终答案。

### 3.2 证据库（Evidence Bank）

TRACE 的核心是动态构建的证据库 \(E\)，负责保存智能体整个轨迹中已经收集的事实性信息。作者发现，相比直接把未经整理的全部对话交给 LLM 裁判，结构化组织输入、工具与返回结果之间的关系，更有助于评价效率及幻觉。

在第 \(t\) 步，系统产生新的证据条目：

\[
e_t=(a_t,i_t,o_t),
\]

随后将其加入证据库。第 \(t\) 步后的累计证据表示为：

\[
E_t=\{e_1,e_2,\ldots,e_t\}=\bigcup_{k=1}^{t}\{e_k\}.
\]

因此，证据库提供了智能体与外部环境交互的逐步、客观记录，让评价器能依据已经出现的可验证信息判断推理是否合理。

### 3.3 轨迹评估指标

#### 3.3.1 效率（Efficiency）

理想的智能体应尽可能直接地得到正确答案，避免无效步骤。TRACE 并不尝试枚举所有可能解法并证明全局最短路径，而是在**智能体实际使用的工具集合中**检测不必要的证据。

具体而言，在智能体给出最终答案之后，LLM 评价器综合最终回答 \(Ans_{final}\) 和全部证据库 \(E_n\)，筛选出逻辑上推导最终回答所必需的最小证据子集 \(E_{min}\subseteq E_n\)。其余条目构成不必要的证据 \(E_{unnecessary}=E_n\setminus E_{min}\)。效率定义为：

\[
\operatorname{Eff}(T)=\frac{|E_{min}|}{|E_n|}
=1-\frac{|E_{unnecessary}|}{|E_n|}.
\]

效率为 1，表示轨迹中没有可识别的冗余证据；较低的分数表示智能体使用了更多对结果无助的步骤。需要注意，该指标衡量的是已观察轨迹中的必要性，而不是从所有潜在路径中求得数学意义上的绝对最优操作数。

#### 3.3.2 幻觉（Hallucination）

如果智能体的思考过程偏离已经获取的事实，就可能产生幻觉。TRACE 检查每一步思考 \(th_t\) 是否能够由之前累积的证据 \(E_{t-1}\) 逻辑推导出来。作者使用一个 LLM 实现的布尔判断函数：

\[
\operatorname{IsGrounded}(th_t,E_{t-1}).
\]

当该函数返回 false 时，定义步骤幻觉指标：

\[
H(s_t)=
\begin{cases}
1,&\neg\operatorname{IsGrounded}(th_t,E_{t-1}),\\
0,&\text{其他情况}.
\end{cases}
\]

轨迹幻觉率计算为每一步幻觉指标的平均：

\[
H(T)=\frac{1}{n}\sum_{t=1}^nH(s_t).
\]

第 1 步的证据库 \(E_0\) 为空，因此评价仅根据其思考内容与已给定任务判断。论文采用比较严格的操作性定义：即使智能体引用的知识并非凭空编造，只要其事实性推断**没有出现在证据库中**，也可能被标为未被证据支撑。这一点在解释论文的“幻觉”结果时尤其重要。

#### 3.3.3 适应性（Adaptivity）

真实工具生态中的 API 可能升级、接口不兼容、超时或被限流。可靠的智能体必须能够识别错误，并在工具不可用时采取合理的替代路径。

设 \(F\) 为工具调用失败的步骤索引集合。对于每个 \(t\in F\)，TRACE 检查后续步骤 \(s_{t+1}\) 的思考与动作。如果智能体承认前一工具失败，并采用合理的替代策略（例如改用功能类似的工具，或通过其他方法继续任务），则适应性判定为 1；如果重复调用同一失败工具或陷入停滞，则为 0。最终可对失败事件取平均作为适应性指标。

## 4 实验：TRACE 的元评价

### 4.1 Meta-GTA 与 Meta-m&m’s 数据集

为了检验 TRACE 是否能够准确识别智能体推理过程的质量，作者设计了元评价数据集，即专门用于**评价评价框架本身**的数据。其基础为两个已有的多模态工具调用基准 GTA 与 m&m’s。

对于 GTA，研究首先根据原始高质量、人工整理的标准轨迹，生成多条在工具依赖关系上同样合法的参考轨迹。随后有目的地插入冗余工具调用、缺乏证据的思考，以及面对不可用工具时的适应性步骤，并对每个步骤赋予对应标签。对于 m&m’s，研究也生成多条合法路径并插入冗余步骤，但由于其数据只包含动作序列、没有中间思考，不对幻觉与适应性进行此类扩增评价。

在 Meta-GTA 中，幻觉检测准确率、效率检测准确率以及适应性检测准确率，均通过相应的步骤预测与标注是否一致计算：

\[
Acc_H(T)=\frac{1}{n}\sum_{t=1}^{n}\mathbf 1[H(s_t)=H_{label}(s_t)],
\]

\[
Acc_{Eff}(T)=\frac{1}{n}\sum_{t=1}^{n}\mathbf 1[I(s_t)=I_{label}(s_t)],
\]

\[
Acc_{adp}(T)=\frac{1}{|F|}\sum_{t\in F}\mathbf 1[Adp(s_{t+1})=Adp_{label}(s_{t+1})].
\]

对于 Meta-m&m’s，由于没有中间思考，效率评估采用二值准确率：只有预测的无效步骤数量恰好等于标签数量时才计为 1。

### 4.2 元评价结果

原文表 1 比较直接的 LLM-as-a-Judge 基线与 TRACE 在 Meta-GTA 和 Meta-m&m’s 上的表现。多数模型在使用 TRACE 后，在效率、幻觉和适应性检测上获得更准确的判断；小型开源模型的改善尤其显著。例如在 Meta-GTA 的效率检测上，Llama-3.1-8B 从 55.67 提升至 70.46；Llama-3.3-70B 从 76.55 提升至 90.03；GPT-4.1 从 81.45 提升至 94.24。Claude-Sonnet-4 的效率判断从 86.08 提升至 94.64。

作者将这部分改善归因于证据库的结构化设计，但也指出元评价数据是通过向高效轨迹插入已知冗余步骤得到的；准确识别插入项是指标奖励的核心行为。因此，这些结果直接证明 TRACE 能发现此类人为设计的轨迹缺陷，不能未经验证地外推为对所有真实复杂轨迹都具有同等能力。

### 4.3 与既有轨迹评价方法的比较

作者选择 PIPA 作为对照。PIPA 研究交互式规划智能体的状态一致性（state consistency），它在一定程度上可以反映是否发生冗余工具调用，因此与 TRACE 的效率指标存在关联。

针对“同一个问题存在多条有效轨迹”的情况，作者在 Meta-GTA 中取出对应样本：这些轨迹都正确且高效，只是工具调用顺序不同，因此理想的评价结果应接近 100 分，并具有很低的轨迹间标准差。原文表 2 表明，TRACE 的效率分数更准确、波动更小；而 PIPA 以累积状态衡量当前状态一致性，在并行处理多个输入文件时更容易出现分数下降。TRACE 直接从整条轨迹中找出对最终答案无关的证据，因而对不同工具顺序较为稳健。

原文表 3 对所有 Meta-GTA 轨迹进行比较，TRACE 在各模型上的效率评估准确率均高于 PIPA。尤其在 Llama-3.1-8B 等小模型上，使用证据库的优势明显。

## 5 使用 TRACE 评价工具增强型 LLM 智能体

此前 GTA 等工具智能体基准主要使用最终答案准确率衡量能力，容易掩盖推理质量差异。本节通过 TRACE 同时评估最终准确率、效率、幻觉和适应性，观察不同智能体的失败机制。

### 5.1 实验设置

参与实验的九个智能体模型分别为 Claude-Sonnet、GPT-4.1、o3-mini、Llama-70B、Llama-8B、Mixtral-8x7B、Mistral-7B、Qwen-72B 和 Qwen-7B，其中前三个为闭源模型。任务来自包含多模态与多输入问题的 GTA 数据集。

TRACE 内部使用 Claude-Sonnet、GPT-4.1、Llama-70B 和 o3-mini 作为评价器。这些模型依据第 4 节元评价结果选出，用于分别计算效率、幻觉率和适应性。为精确测试适应性，作者向 GTA 原始工具集注入若干名称与真实工具相近的**伪工具**。当智能体调用此类工具时，环境返回“工具不可用”错误，并记录智能体能否在接下来的一步切换到合适的工具。

除了 TRACE 指标，论文还沿用 GTA 的评分协议记录指令遵循错误和答案准确率。指令错误包括选择不存在的工具、或工具参数格式错误，按照对应错误数占轨迹长度的比值衡量。对于选择题（MCQ）使用二元准确率；长文本回答（LTR）采用 All-MPNet-Base-V2 的嵌入余弦相似度；图像输出（IMG）采用 GTA 中的参数嵌入相似度。总体准确率为样本级微平均，以反映不同问题类型的实际数量分布。

**执行反馈机制。** 为避免智能体因为小型、可修复错误而过早终止，若其调用未列入工具表的函数或传入错误格式的参数，环境返回类似 `tool not in the list` 或 `tool execution error` 的错误信息，而不是直接停止。这样可以收集更长、更完整的轨迹来分析智能体的纠错能力。不过第一次调用错误仍会被计入“工具不存在”或“参数格式错误”的统计，并不会因之后恢复而消失。

**向多智能体系统扩展。** TRACE 不限于标准 ReAct 单智能体。对多智能体系统（MAS），可以为各子智能体维护独立证据库，利用全部证据库检查 orchestrator（编排者）与子智能体的幻觉，并在最终答案正确时评价是否收集了不必要的信息。作者在附录 D.1 以 Magentic-One 与 GAIA 数据集说明这种扩展。

| Mixtral-8x7B | 0.1631 |
| Mistral-7B | 0.0154 |

**总体表现。** 闭源模型取得最好的总体性能，但在复杂工具增强任务上仍有较大改进空间。在同一开源模型家族内部，更大参数规模通常更有优势；然而不同家族之间，模型参数量并非唯一决定因素：例如 Qwen-7B 的总体准确率超过 Llama-3.3-70B 与 Mixtral-8x7B，而 Qwen-72B 接近一些较强的闭源模型。这提示模型架构、训练方式与工具使用适配可能同样重要。

较强的闭源模型往往有很低的指令错误率；较小开源模型更容易在长上下文中出现工具选择或参数格式问题，因此可能受益于额外的工具参数检查与格式修正机制。

#### 5.2.1 效率

作者主要针对最终答案正确的轨迹计算效率。总体趋势是，大模型通常生成较短、冗余步骤较少的轨迹，但这一趋势并不绝对。一项重要观察是：轨迹越低效、包含越多无关步骤，产生错误答案的风险越高。原因可能是长轨迹增加上下文长度，使后续推理更难维持准确。Mistral-7B 在本实验中没有成功得到正确答案，因此对应的成功轨迹效率指标没有报告。

作者承认“只在成功轨迹上计算效率”可能产生幸存者偏差，因此在附录 D.2 还测量失败轨迹的效率。结果同样表明，失败轨迹通常有更多冗余操作。研究进一步建议可以考虑将准确率与效率加权结合，以获得更全面的综合性能度量。

#### 5.2.2 幻觉

幻觉与总体准确率具有较高相关性：推理中没有根据证据的信息越多，最终回答往往越容易错误。o3-mini 的幻觉率较低，作者认为这可能与推理模型更注重深层推理、严格使用已收集证据有关。

但高分未必都是良好表现。例如 Mistral-7B 的低幻觉分数并不代表它完成了任务，而可能源于其经常认为自己无法继续，于是提前终止。**因此，不能脱离完成率单独解释幻觉指标。**

#### 5.2.3 适应性

适应性衡量智能体在尝试使用一个与真实工具名称相似、但不可用的工具后，能否接着选用有效工具。作者发现 GPT-4.1 与 Qwen-72B 虽然总体准确率较高，但适应性相对有限，说明加强工具错误恢复有望进一步提升性能。

TRACE 使模型能力比较更加细致：如果只看总体准确率，Qwen-72B、GPT-4.1 与 o3-mini 似乎处于相近水平，但 Qwen-72B 的效率较高、幻觉相对较多；o3-mini 几乎不产生幻觉，但在工具失败后的继续执行上较弱。Llama-70B 与 Qwen-7B，以及 Llama-8B 与 Mixtral-8x7B，也分别表现出总体成绩接近、底层轨迹行为却明显不同的情况。这意味着不同模型需要不同改进策略，开发者也可以按效率、稳定性、推理可靠性等重点选择模型。

#### 5.2.4 Token 消耗分析

原文图 4 将模型总体准确率、每个问题的平均工具调用轮次及输出 token 数联系起来。为了统一统计，作者在 o3-mini 的输出计数中排除了额外的推理 token。除难以产生有效回答的 Mistral-7B 外，模型进行更多轮工具交互通常伴随较低的总体性能；输出 token 数增加也与准确率下降相关。作者推测，超过任务所需的输出长度可能引入不必要的信息和噪声，拉长上下文并削弱推理，尤其影响小模型。对于低置信度小模型，有时**限制无效的长链推理**可能比无限增加思考 token 更有效。

## 6 结论

本文讨论工具增强型智能体评价中“只看最终答案”的不足，并提出 TRACE，以不依赖单条预定义参考轨迹的方式综合衡量推理过程。三个关键指标为效率、幻觉与适应性。TRACE 提供了比传统准确率更接近实际任务过程的能力表征：即便模型的最终分数接近，其工具调用效率、证据使用及错误恢复能力也可能不同。作者认为，这样的过程评价有助于更准确地理解智能体能力，也为改进智能体设计提供了方向。

## 附录 A　完整相关工作

### A.1 工具增强型 LLM 智能体

外部工具极大地扩展了大语言模型能力。CoT 揭示了中间推理步骤对复杂问题的重要性，ReAct 通过交错执行“思考—动作”使智能体能够动态规划、执行并调整策略。在这些基础研究之后，ToolLLM 将工具调用扩展到超过 16,000 个现实 API；TORA、MMedAgent 和面向金融交易的多模态模型将工具智能体推广至数学、医疗和金融；MLLM-Tool 等研究则拓展了对多模态输入的理解与行动能力。同时，EasyTool 等研究关注精简工具指令，自主交互与工具文档优化研究关注提升工具学习效率。

### A.2 工具增强型智能体的评价

随着智能体任务越来越复杂，GAIA、MetaTool 等基准分别从现实问题解决和工具选择出发评估能力。GTA 与 m&m’s 等基准依赖最终答案或单条标准轨迹，容易惩罚有不同但合法执行路径的模型；枚举所有正确路径又难以扩展。最近研究开始关注过程级评价，不过 ToolBEHonest 主要检测幻觉，PIPA 重视状态一致性，尚不足以覆盖效率、适应性等多个维度。同时，多模态多输入任务使多条合理轨迹产生评价方差，进一步体现了参考路径无关评价的必要性。

## 附录 B　元评价过程细节

### B.1 数据集生成与验证

对于 Meta-GTA 与 Meta-m&m’s，研究先利用 GPT-4o 为原始单条参考轨迹生成多个合法变体（相关提示词见图 7），接着使用图 8–10 的提示词注入冗余步骤、幻觉思考和工具失效后的适应性动作。原始参考轨迹始终保留，以便发现 TRACE 将正常步骤误判为无效或幻觉的错误。

质量控制首先由 Claude Sonnet 4.0、GPT-4o 与 Gemini Pro 三个模型对每条数据作验证（图 11–14）。研究从每个模型的验证结果中随机抽取 100 条进行人工抽查，并报告 98.79% 的一致率；最终仅保留三个模型都认为“valid”的数据。

## 附录 D　进一步分析

### D.1 多智能体系统扩展

研究以 Magentic-One 和 GAIA 为例，说明 TRACE 可以从 ReAct 扩展到多智能体架构。系统可为 orchestrator 与各子智能体分别维护证据库，综合证据库检测幻觉，并按照相似方式评价效率。原文表 7 报告不同评价器对 Magentic-One 的分析：Claude-Sonnet-4 得到效率 93.09、幻觉维度 79.58；GPT-4.1 为 97.07 和 81.38；o3-mini 为 88.06 和 84.50；Llama-3.3-70B 为 93.16 和 81.40。该实验中的任务准确率均为 20.45。该部分说明 TRACE 不依赖简单的 Action–Input–Output 序列，可以以少量改动适配更复杂的智能体架构。

### D.2 失败轨迹的效率

只计算正确轨迹的效率会产生幸存者偏差，因此研究还评估失败轨迹，并在表 8 中与成功轨迹效率对比。结果显示，失败轨迹普遍比成功轨迹更低效：无关工具调用越多，得到正确答案的机会越小。这与正文“尽快识别并使用必要工具有助于提高成功率”的发现一致。论文还提出一种可行的综合指标方向，即将准确率与效率组合计算，以减轻幸存者偏差的影响。原文完整矩阵见 [表 8（第 15 页）](https://arxiv.org/pdf/2510.02837#page=15)。
