## 摘要（中文翻译）

将大语言模型（LLM）作为通用智能体进行评估，对于理解其能力并推动其融入实际应用十分重要。然而，这一评价过程面临巨大挑战。其一，如何在统一框架中对跨越多种场景的智能体表现进行基准测试，尤其是如何维护**部分可观测的环境**并支持**多轮交互**；其二，现有评价框架大多只关注最终任务成功率，对任务执行过程的揭示十分有限，难以深入理解模型的能力。

为此，作者提出 **AgentBoard（AGENTBOARD）**，一种面向 LLM 智能体的综合基准及开源分析式评估框架。AgentBoard 提出细粒度的**进度率（Progress Rate）**指标，以捕捉智能体执行过程中逐步取得的进展，并提供能够从多个角度进行分析的完整评估工具。它不仅能揭示 LLM 智能体的能力与局限，也将模型表现的可解释性置于评价中心。研究希望借此帮助理解智能体行为，并促进更强大智能体的发展。

## 1. 引言（中文译述）

能够自主感知不同环境并采取行动的通用智能体，是人工智能领域的重要发展目标。近年来，LLM 在语言理解、规划以及多轮交互方面出现新能力，带动了基于语言模型的自主行动系统。但智能体评价不能照搬单轮问答任务：真实应用往往要求模型与环境反复互动、获得不完整观察、探索未知状态，并在多步操作中持续调整计划。

作者指出，多数现有基准未能同时覆盖**任务多样性、多轮交互、部分可观测性和过程评价**。仅统计最终任务成功率的做法尤其存在问题：对于困难任务，多个模型的最终成功率可能都接近零，但其中有的模型已完成大部分子目标，另一些则几乎没有进展。最终的二元成功与失败会掩盖这些重要差异，也不利于分析发生问题的具体阶段。

AgentBoard 提供四大类、共 **9 种任务环境和 1,013 个实例环境**，从具身任务、游戏到网页和工具操作。开发团队为任务定义或人工标注子目标，给出统一的进度率指标。与此同时，作者开发了支持交互式可视化的分析平台，帮助研究者查看难例与易例的表现、长程互动、行动落地（grounding）准确性、不同子能力与逐步执行轨迹。

![图 1：AgentBoard 任务与分析界面全貌](./images/figure-1-p002.png)

论文主要结论包括：GPT-4 在大多数智能体能力上领先；强模型更能在多轮互动中保持推进，而不少开源权重模型表现出较大的长程性能损失；智能体总体表现依赖于更基础的能力，包括正确执行动作、环境建模、自我反思与规划，因此有必要从多个维度解释结果。

## 2. AgentBoard 整体框架

### 2.1 统一的多轮反应式智能体（Reflex Agent）

AgentBoard 使用统一接口来组织不同任务：智能体接收文本形式的环境观察，生成文本动作，环境执行有效动作并返回状态变化或错误反馈。作者采用部分可观测马尔可夫决策过程（POMDP）的形式描述此类交互：

\[
\langle g,S,A,O,T\rangle
\]

其中 \(g\) 是目标，\(S\) 为环境状态空间，\(A\) 为合法动作空间，\(O\) 为包含反馈的观察空间，\(T:S\times A\to S\) 表示状态转移。Agent 根据目标、当前环境和历史记忆生成动作；一段轨迹是环境状态与动作依次发生的序列。论文式（1）给出轨迹在策略 \(\pi\) 下的概率表达：

\[
p_\pi(\tau)=p(s_0)\prod_t\pi(a_t\mid g,s_t,m_t)T(s_{t+1}\mid s_t,a_t)
\]

这个统一接口不追求复杂智能体架构，而是尽可能减少系统层差异，使同一底层 LLM 在不同环境的表现可比较。论文主要采用 **Act-only** 提示方式，并通过滑动窗口保留最近的交互历史，防止对话过长而使智能体直接终止。框架也能替换成 ReAct 等其他提示策略；作者在附录中提供相关消融实验。

### 2.2 核心指标：细粒度进度率（Fine-grained Progress Rate）

作者认为，若一个任务已经完成 90% 的工作但最终失败，其表现不应与完全没有取得进展的任务等同。为此，在交互时刻 \(t\) 定义进度率 \(r_t\)，反映从开始到目前为止智能体实现的最高目标进度，取值范围为 \([0,1]\)，任务完整实现时为 1。

对于可以直接测量“当前状态与目标状态相似程度”的任务，使用连续匹配型进度率：

\[
r_t^{\mathrm{match}}=\max_{0\le i\le t}f(s_i,g)
\]

其中 \(f(s_i,g)\) 测量当前或历史状态与目标之间的匹配程度。这适合电子表格编辑等有明确最终状态、能够计算单元格匹配比例的任务。

对于需要完成多个阶段性目标、但中间状态难以用连续距离衡量的任务，将总目标分解为 \(K\) 个子目标 \(g_1,\dots,g_K\)，使用离散子目标完成情况：

\[
r_t^{\mathrm{subgoal}}=\max_{0\le i\le t}\left[\frac{1}{K}\sum_{k=1}^{K}f(s_i,g_k)\right],\qquad f(s_i,g_k)\in\{0,1\}
\]

公式中的最大值意味着进度率记录到目前为止达到过的最高进展，而不是只记录某一个当前时刻。这能够减少暂时回退或探索动作造成的剧烈波动。这里保留论文式（2）的实际思想与符号，原 PDF 第 5 页提供完整排版。

作者强调，**进度率并不等同于最终成功率（Success Rate）**。后者统计在允许的最大交互次数内完全完成任务的比例。进度率只是从过程维度补充评价，既不能保证所有必要子目标都已被定义，也无法自动证明每个子目标标注均正确。

举例而言，“清洗鸡蛋并将其放入微波炉”可以依次分解为打开冰箱、取得鸡蛋、使用水槽清洗鸡蛋、将鸡蛋放入微波炉等子目标。任务实施者可采取绕路或不同动作序列，只要经过的状态满足相应子目标，仍可产生进度。这也意味着 **参考的子目标序列不是要求每一步动作必须与某个唯一 GT 轨迹相同**。

## 3. 基准任务组成

AgentBoard 覆盖四种场景和九个任务环境：

| 场景 | 环境（缩写） | 要求与评价重点 |
|---|---|---|
| 具身 | ALFWorld（ALF） | 家居环境探索、日常常识、子目标完成情况 |
| 具身 | ScienceWorld（SW） | 科学实验模拟、物品和状态操作、重新标注子目标 |
| 具身 | BabyAI（BA） | 有限视野的 20×20 网格导航、文字化动作和观察 |
| 游戏 | Jericho（JC） | 文本冒险、未知世界探索及长期状态维护 |
| 游戏 | PDDL（PL） | 形式化规划问题，转换为文本交互 |
| 网页 | WebShop（WS） | 模拟购物、搜索、过滤条件与目标商品选择 |
| 网页 | WebArena（WA） | 真实感网站环境的多步骤导航与操作 |
| 工具 | Tool-Query（TQ） | 天气、电影、学术网络等数据库信息检索 |
| 工具 | Tool-Operation（TO） | 待办事项管理与电子表格编辑等状态改变操作 |

### 3.1 对原有环境的改造

**ALFWorld** 使用家居任务，需要观察房间、找到目标物并逐步执行常识操作。**ScienceWorld** 是更偏科学常识的交互式文本环境。作者认为原环境提供的子目标过于稀疏且权重不均衡，因此重新标注子目标、操作说明和探索房间的相关规则，使进度更能反映模型推进情况。

**BabyAI** 原本基于图像观察与张量动作，本文改为文本观察和文本动作，并补齐稀疏子目标标注。**Jericho** 需要智能体通过行动认识幻想世界，原始完整任务可能很长（文中提到约 50—300 步），因此作者改写阶段性目标，把游戏控制在大致 15 个子目标以内，以适应上下文受限的 LLM。

**PDDL** 使用 Gripper、Barman、Blocksworld、Tyreworld 等规划环境，并改写为文字观察形式；对于能与目标状态直接比较的任务采用匹配进度率。**WebShop** 修改越界及错误对象交互时的反馈，并扩展商品匹配规则。**WebArena** 将 URL 与页面内容的匹配情况用于连续进度计算。

**Tool-Query** 包含天气、电影和学术网络查询三个子环境；即使 LLM 能直接猜出答案，基准也要求它通过恰当工具轨迹访问数据库，才能算正确完成。**Tool-Operation** 涉及待办项目与表格操作；待办任务主要使用子目标完成率，电子表格则比较当前表格与目标表格单元格状态。

### 3.2 标注核查与指标合理性验证

作者对人工标注的子目标进行了多轮人工核查，并开展独立的人工进度评价研究。论文使用 GPT-4、GPT-3.5-Turbo 和 DeepSeek-67B 生成轨迹，对八类任务的轨迹各抽取 **60 条**，由 **4 位作者**分别在不知道自动进度率的情况下赋予 0%、25%、50%、75% 或 100% 的进度判断，再将人工平均得分与自动进度率比较。

![图 3：进度率和人工进度判断的一致性验证](./images/figure-3-p006.png)

原文报告 **各项任务的 Pearson 相关系数都超过 0.95**，并使用 Fleiss’ Kappa 描述人工标注者的一致性。这是作者用于支持进度率有效性的证据，但注意：高度相关不等于证明每一道任务中所有子目标或标准答案均无错误。论文的附录 J 与 L 讨论了子目标修订和核查过程。

## 4. 模型实验与分析

### 4.1 整体性能比较

![表 3：各模型任务成功率与进度率对比](./images/table-3-p007.png)

作者比较了多个闭源和开源权重模型。结果表明，**GPT-4 在整体表现上领先**，但按任务类别拆开后仍存在不足，例如复杂的文本游戏与网页操作仍然困难。与最终成功率相比，进度率能够显示模型在未完成任务时是否实际上达成了部分目标，避免所有失败都落入同一个零分区间。

### 4.2 行动落地准确性（Grounding Accuracy）

![表 4：不同任务类别的动作落地准确性](./images/table-4-p008.png)

Grounding 关注语言模型是否能够从自然语言或状态描述生成环境真正允许的动作，主要识别动作格式、工具使用与参数输入方面的错误。在工具环境中，模型即使能正确理解用户意图，仍可能因工具调用不合法而失败。论文将这种能力与更高层的规划、世界建模和自我反思区分开来。

### 4.3 难例和易例分析

![表 5：简单与困难任务上的进度率、成功率](./images/table-5-p008.png)

作者依据任务需要满足的子目标或条件数量将测试分成简单与困难两组。不同模型在困难任务上的进度率和成功率普遍下降，说明多子目标组合和长任务依赖仍是挑战。仅报告总体平均分可能掩盖在困难样本上出现的严重性能退化。

### 4.4 长程交互过程

![图 4：进度率随交互步数变化](./images/figure-4-p009.png)

在 ALFWorld 和 PDDL 中，GPT-4、Claude 2 等较强模型可在约 30 步的观察窗口内持续推进；但在 WebArena 和工具环境中，进度可能较早达到峰值并停滞。许多开源权重模型在大约 6 步后就难以持续取得进展（论文也提到 Llama3-70B 和 DeepSeek-67B 属于表现较强的例外）。因此，研究智能体时应同时报告**最终成功率、进度曲线和交互长度**，而不是只考察第一次工具调用是否正确。

### 4.5 六种子能力

![图 5：模型的六类子能力分析](./images/figure-5-p009.png)

作者通过任务属性评分，从六个维度描述智能体表现：

| 子能力 | 中文含义 | 主要观察点 |
|---|---|---|
| Memory | 记忆 | 能否有效使用较早轮次的信息 |
| Planning | 规划 | 能否把目标分解为可执行子任务 |
| World Modeling | 世界建模 | 是否理解环境结构及行动后果 |
| Self-Reflection | 自我反思 | 能否利用失败反馈改变策略 |
| Grounding | 动作落地/执行对齐 | 能否生成环境接受的动作与参数 |
| Spatial Navigation | 空间导航 | 能否在有位置关系的环境中到达目标 |

该子能力评分反映论文对不同任务所需能力的判断，不能直接看作由独立实验精确测量出的六个心理学潜变量。研究者可以用它分析不同任务的结构与表现，但跨任务比较时仍需关注任务难度及评分定义。

## 6. 相关研究（中文译述）

早期强化学习提供了通用的序贯决策框架，但在样本效率与泛化方面有局限。利用 LLM 的语言理解和分步推理能力，可以通过提示词与环境互动完成任务；额外训练则可能进一步提升智能体能力。作者对照已有的 AgentBench、GAIA、MINT、API-Bank、ToolEval 等基准，指出 AgentBoard 的重点是将 **多场景、部分可观测性、多轮交互和可视化的中间进度**统一起来，而不是设计新的单轮选择题集合。论文聚焦文本环境，不覆盖全部视觉或机器人传感器输入。

## 7. 结论与局限性（中文译述）

本文提出 AgentBoard 作为通用 LLM 智能体的基准，同时提供可扩展的开源分析框架、统一进度率以及交互式可视化工具。与仅输出最终成功率的方式相比，该系统能够展示任务逐步实现的程度以及模型在长程交互、动作落地、记忆、规划等维度的差别，有助于更深入地分析智能体的性能。

论文自身承认两项主要局限。第一，进度率依赖**人工标注的子目标**。作者考虑过使用 LLM 自动标注，但当时模型在 AgentBoard 任务上的表现不足以可靠地生成所需的子目标。第二，为了统一评价环境，研究主要采用模拟环境；真实环境中参考答案不稳定、执行具有风险，且存在安全与权限问题，后续需要进一步研究。

对于基准可靠性研究，这意味着：**只要评价依赖“子目标已完成”作为中间真实值，就必须继续检验这些子目标的必要性、充分性、标注一致性以及是否排斥合法的替代路径。** 这是基于论文方法的研究延伸，并不是论文已经完整解决的问题。
