## 摘要

地球观测（Earth Observation，EO）对于理解地球系统不断变化的状态至关重要。尽管近年来多模态大语言模型（Multimodal Large Language Models，MLLMs）推动了 EO 研究的发展，但它们仍缺少解决复杂任务所需的多步推理与领域专用工具使用能力。基于智能体（Agent）的方法提供了有前景的方向，但现有工作仍处于早期阶段，通常局限于 RGB 图像感知、浅层推理，且缺少系统性的评价协议。

为克服这些限制，本文提出 **Earth-Agent**：一个基于模型上下文协议（Model Context Protocol，MCP）的工具生态，统一支持 RGB 与光谱类 EO 数据，使系统能够超越预训练 MLLM 的既有能力，完成跨模态、多步骤、定量的时空推理。Earth-Agent 可以动态调用专家工具和模型，完成地球物理参数反演、定量时空分析等复杂科学任务。

为实现综合评价，作者进一步构建 **Earth-Bench**，包含 **248 道专家编写的任务、13,729 幅图像**，覆盖光谱、地球观测产品和 RGB 三种数据模态，并引入同时评估推理轨迹与最终结果的双层评价协议。论文通过改变 LLM 主干模型、与通用智能体框架比较、与遥感 MLLM 在遥感任务上比较等实验，验证了 Earth-Agent 的有效性及潜力。这一工作标志着 EO 分析从单图像感知向具有科学依据的多模态、多步骤智能分析发展。

## 1 引言

地球观测在理解地球系统的空间和时间演变中扮演重要角色，广泛应用于城市规划、农业、资源管理、建筑物提取和灾害监测。按照数据形式，EO 数据可以分为两类：一类是**感知型数据（Perceptual Data）**，典型代表为与人眼视觉接近的 RGB 图像；另一类是**原始观测数据（Raw Observational Data）**，包括原始光谱数据（Spectrum）和在 Google Earth Engine、NASA Earthdata 等地理数据库中存储的加工型地球观测产品（Products）。两类数据在 EO 研究中都不可或缺：前者提供直观、易于人类理解的观察内容，后者具有丰富的光谱及时空信息，能够支持量化分析。

近年 MLLM 在遥感视觉问答、场景分类、目标检测及语义分割等任务上取得明显进展。然而，论文指出，主流 MLLM 方法仍存在四方面根本限制：

1. **数据模态狭窄。** 通常只能处理 RGB，难以直接支持热红外（TIR）、合成孔径雷达（SAR）或高光谱等其他 EO 模态。
2. **输入规模有限。** 通常一次处理一张或少量图像，难以分析大型 EO 数据集合。
3. **推理层次较浅。** 多数停留在问答、分类等单步任务，难以执行跨多阶段的复杂分析。
4. **不能灵活集成专家工具。** 推理主要依赖模型参数中的静态知识，无法随任务动态调用外部科学算法和专家模型。

这些限制引出了第一项研究问题：如何超越传统 RGB 感知及单步推理，使模型综合不同 EO 模态并完成复杂的多步骤科学分析？

工具增强型 LLM Agent 为此提供了可行路径。与预训练 MLLM 不同，智能体通过调用外部工具，将语言模型的规划和推理与真实计算环境结合，既可以处理多模态数据，也可以同时处理较多输入文件，完成专业的数据检索、计算与分析。不过现有 EO Agent 多聚焦变化检测、分类、目标检测和场景描述：例如 Change-Agent、RS-Agent、RS-ChatGPT、ThinkGeo 等尚不能全面覆盖复杂定量地学工作流；UnivEarth 侧重通过 LLM 生成 GEE 代码，但在复杂真实任务中仍存在较高执行失败率。现有基准也大多重视最终答案，缺少对**工具调用轨迹**的系统验证。

由此产生第二个问题：如何设计同时包含有组织的工具生态、感知与光谱数据处理，以及严格评价机制的地球观测智能体？

Earth-Agent 的回答是：在 MCP 协议之上，把 LLM/ReAct 与 **104 个专业工具**连接起来，按 **Index（指数）、Inversion（反演）、Perception（感知）、Analysis（分析）、Statistics（统计）**划分功能；同时通过 Earth-Bench 的终局和过程双层评价检验工具调用及科学结果的可靠性。

## 2 相关工作

### 2.1 基于 MLLM 的地球观测研究

早期遥感 MLLM 主要处理单幅遥感图像的描述生成和视觉问答，将图像特征与自然语言对齐。随着数据集规模和基础模型能力提升，研究逐渐涵盖更多感知任务，例如 GeoChat 的交互式场景理解、RS-GPT 的描述生成和问答；更新的 ChangeCLIP 涉及双时相变化描述，SkyEye-GPT 则尝试视频数据分析。但总体而言，这些方法仍以 RGB 图像为中心，对于需要专业工具和多步运算的分析任务支持不足。

### 2.2 基于 Agent 的地球观测研究

工具增强智能体在代码生成、网页检索和视频理解等通用任务中已显示价值，但 EO 领域的研究仍相对早期。Change-Agent 聚焦双时相变化检测；RS-ChatGPT 与 RS-Agent 将 LLM 和预训练检测/分割模型相结合；ThinkGeo 探索简单空间计算的智能体工作流；UnivEarth 则要求模型生成 GEE 代码来处理光谱数据。作者认为，这些系统仍存在模态覆盖窄、推理较浅、缺乏统一工具生态与完整轨迹评估的问题。与此同时，现有 EO 基准对任务类型及细粒度注释的覆盖不够，难以同时区分“答案是否正确”和“工作流为什么出错”。

## 3 Earth-Agent 框架

### 3.1 工作机制

Earth-Agent 接收用户目标 \(g\)，解释用户问题与工具输出，从模块化工具集中逐步选择动作直至完成任务。作者采用具有 ReAct 风格的**部分可观测马尔可夫决策过程（POMDP）**刻画这一流程，形式化为 \(\langle g,S,A,O,T\rangle\)。其中，\(S\) 为空间数据文件、栅格值等难以被语言模型直接观察的环境状态，\(A\) 是工具调用动作空间，\(O\) 是文本、数值和图像等工具观测空间，\(T\) 是状态转移函数。

智能体基于任务目标和由历史动作、历史观测构成的记忆 \(m_t\) 决定下一工具动作，记作：

\[
 a_t\sim\pi(a_t\mid g,m_t).
\]

一次交互循环包括四步：**① 工具调用**，根据任务目标及现有记忆选择工具并执行；**② 记忆更新**，将工具动作及输出加入历史；**③ 思考**，利用更新的记忆分析下一步所需操作及输入参数；**④ 行动**，调用下一工具并接收新反馈。上述 ReAct 循环直到满足停止条件，得到最终结果和可回溯的工具使用轨迹。原文第 5 页还给出了整个轨迹联合概率分布的形式化表达，完整符号以原始论文为准。

### 3.2 专业工具集

系统集成 **104 项专业工具**，按照功能划分为五组：

- **Index Toolkit（指数工具集）：** NDVI、NDWI、NBR 等植被、水体、火烧迹地及其他遥感指数运算。
- **Inversion Toolkit（反演工具集）：** 地表温度（LST）、可降水量（PWV）、植被含水量、海冰密集度等地球物理参数反演。
- **Perception Toolkit（感知工具集）：** 场景分类、目标检测和影像分割等视觉任务。
- **Analysis Toolkit（分析工具集）：** 时空趋势分析、季节性分解、变点检测和空间自相关等量化推理。
- **Statistics Toolkit（统计工具集）：** 方差、偏度、批量运算、云掩膜及其他大规模数据预处理和统计计算。

这些工具组共同支持从感知到光谱、从描述性问题到定量分析的地球观测工作流。详细工具清单位于原文附录 G，分别由表 13–17 列出。工具的代码名称、参数类型和输出约束在附录原表中保留原样。

### 3.3 双层评价协议

过去不少基准主要报告最终答案正确率，而忽略达到结果的推理轨迹。本文采用双层评价协议：**端到端（End-to-End）**评价整个任务是否成功，**逐步骤（Step-by-Step）**评价中间工具调用过程。前者帮助衡量结果质量，后者可以定位规划或执行错误。

端到端层面报告两项指标：

1. **Accuracy（准确率）：** 最终输出是否与专家标注答案一致。
2. **Efficiency（效率比）：** 预测轨迹与专家轨迹的工具调用次数比，即 \(|\tau|/|\tau^*|\)。需要特别注意：原文采用的是调用次数比，并非越大越好的常规效率评分。

逐步骤层面采用四项指标：

1. **Tool-Any-Order（TAO）：** 不考虑先后顺序，只检查所需工具是否被覆盖。
2. **Tool-In-Order（TIO）：** 检查专家工具序列是否按正确次序在预测序列中出现。
3. **Tool-Exact-Match（TEM）：** 计算预测与专家工具序列的最长共同前缀比例。
4. **Parameter Accuracy：** 在前缀匹配条件下，同时要求工具身份与输入参数结构一致。

其中 TAO、TIO、TEM 与参数准确率互为补充，可以区分“找到了正确工具”与“以正确顺序、正确参数执行全部工具”之间的差异。完整数学定义和公式 (1)–(6) 参见附录 B.2。

## 4 Earth-Bench 基准

### 4.1 基准概况

Earth-Bench 面向真实地球科学分析场景，包含 **RGB 图像、原始光谱数据、加工型 EO 产品**三种模态，覆盖分类、检测、温度监测、天气预测、气候分析、水资源管理、污染监管、植被监测、城市管理、灾害判断、语义分割、视觉定位、计数、变化检测等 **14 类任务**。它尤其强调依赖定量推理的科学分析，而不是仅对图像进行定性描述。

数据集共有 **248 个问题、13,729 幅图像**，每个问题平均涉及约 **55.4 幅图像**、最多 **670 幅**；专家标注的总操作步骤 **1,345 个**，每题平均 **5.42 步**、最多 **19 步**。这比传统单张遥感问答数据集更接近实际的批处理分析工作流。与 PEACE、ThinkGeo、UnivEarth 等 EO Agent 数据集相比，它还要求显式调用更多领域工具，并支持对轨迹逐步核查。

![图 4：Earth-Bench 数据集比较与概况（原图，PDF 第 6 页）](./images/figure-04-p006.jpg)

### 4.2 数据标注流程

数据来自 Google Earth Engine、NASA EarthData 和公开遥感数据集。由 **2 名计算机科学专家、7 名遥感专家和 3 名地球科学专家**组成的团队编制问题和标注。每道题都附有逐步骤的 Python 参考解法，反映需要协调多个工具组才能完成的真实科学工作流。

Earth-Bench 采用两种任务输入设定：**Auto-Planning（自动规划，AP）**对应未明确给出步骤指导的查询，考察 Agent 自主制定工作流的能力；**Instruction-Following（指令遵循，IF）**在用户问题中提供步骤提示，考察按照人类要求执行工作流的能力。两个设定均覆盖完整的 248 道问题。

标注时，专家首先确定需要执行的工具并按顺序将它们组织成 `main()` 形式的 Python 程序，得到 **Python Solution**。随后实际执行程序，记录每次函数调用的参数和输出以及最终结果，得到 **Python Result**。最后把工具名称、输入参数及返回结果转换为结构化 JSON，形成与 ReAct 轨迹相对应的 **JSON Annotation**。这保证了同一问题既有最终答案 Ground Truth，也有可核验的工具轨迹 Ground Truth。

## 5 实验

### 5.1 实验设置

作者评估 **3 个闭源模型和 10 个开源或开放权重模型**，包括 GPT-5、GPT-4o、Gemini-2.5、DeepSeek-V3.1、Kimi K2、Qwen3-Max、Qwen3-32B、InternVL3.5 等；完整版本和接口见附录 B 表 7。对同一模型，报告自动规划（AP）和指令遵循（IF）两种查询设定的结果，并同时计算端到端及步骤级指标。

### 5.2 不同 LLM 主干上的 Earth-Agent

表 1 展示 13 种 LLM 主干的比较。作者指出几个现象：

**观察一。** 接受过工具调用训练的模型，如 GPT-5、Gemini-2.5、DeepSeek-V3.1、Kimi K2 和 Qwen3 系列，在步骤级与终局级评价中通常更强。**GPT-5** 的自动规划最终准确率达到 **65.99%**，指令遵循为 **62.35%**；与此同时，一些开放模型在工具调用匹配等过程指标上超过 GPT-5。

**观察二。** 对许多模型而言，在问题中加入明确步骤指导，能够改善工具选择、参数与最终答案质量，但并非对所有任务和模型都有效。两种输入设定的结果应该分别报告，而不能假设“给出详细操作步骤”一定更好。

**观察三。** 多数模型在 TAO 和 TIO 上得分相对较高，即能够识别大致需要哪些工具，以及大概顺序；但在 **TEM 和 Parameter Accuracy** 上出现明显下降。这说明当前瓶颈不只是发现工具，更在于避免无关步骤、正确设置工具参数并准确完成每一步操作。对于 EO 数据处理，额外且不必要的数据转换可能使后续结果偏离真实值，因此需要特别关注轨迹级准确性。

### 5.3 与通用 Agent 的比较

许多 Earth-Bench 问题需处理上百张图像，因此普通开源 Agent 受输入规模限制而无法直接完成全部任务。作者构建较小但保留多模态多样性的 **Earth-Bench-Lite**：60 道题，三类模态各 20 道。

在这组任务上，Earth-Agent（GPT-5）平均准确率为 **55.83%**；Earth-Agent（DeepSeek-V3.1）为 **47.84%**；Earth-Agent（Kimi K2）为 **45.95%**。作为对比，GPT-Agent、MGX、Manus、Coze 的平均得分分别为 **40.42%、18.60%、26.14%、15.30%**。一些通用 Agent 可以通过即时编程解决简单的光谱任务，但没有专业的时空产品分析工具时，在 Products 模态上表现较弱；MGX 和 Coze 在 RGB 子集上甚至没有成功完成任务。作者据此强调预定义的 104 项地学工具在跨模态分析中的价值。

论文还比较了完成任务的时延：Earth-Agent 的额外计算成本可与通用 Agent 的耗时相比较，且作者认为成功率收益弥补了相应开销。时延构成及批处理优化策略见附录 E。

### 5.4 与遥感多模态大模型的比较

作者在遥感场景分类、目标检测和视觉定位等基准上，将 Earth-Agent 与 MiniGPT-v2、LLaVA-1.5、Sphinx、GeoChat、VHM、LHRS-Bot 等模型比较。Earth-Agent 在 AID、WHU-RS19 上分别达到 **93.42%**、**96.12%**；在 DOTA、HRSC2016 和 DIOR-RSVG 上分别报告 **60.88、65.60、60.46** 的分数，均优于所列基线。

论文认为原因在于已有 MLLM 往往对部分任务擅长、对其他任务不具备扩展能力；Earth-Agent 可以按任务类型动态调用经过训练的专业分类、检测和视觉定位工具，而不要求同一 MLLM 自身掌握所有技能。

## 6 结论

Earth-Agent 将传统 RGB 遥感感知扩展至光谱、加工型产品及 RGB 三种 EO 模态，把预训练 MLLM 的单步推断转换为利用外部工具和模型的多步推理，从而突破传统方法在大量图像输入和定量时空分析方面的限制。Earth-Bench 通过专家可执行轨迹与最终结果标注，为这种能力提供更严格的评测。实验既展示了地学专用 Agent 的潜力，也揭示了精确工具调用及参数正确性仍是当前系统的重要瓶颈。

### B.2 六项评价指标的公式

设预测工具轨迹为 \(\tau\)，专家轨迹为 \(\tau^*\)。原文最终准确率（Accuracy）定义为：

\[
\operatorname{Acc}=\mathbb E_{g\sim G}\left[\mathbf 1\{y=y^*\}\right].
\]

工具调用次数的效率比是：

\[
\operatorname{Eff}(\tau,\tau^*)=\frac{|\tau|}{|\tau^*|}.
\]

令专家工具序列为 \(t^*=(t^*_1,\ldots,t^*_m)\)，模型预测序列为 \(t=(t_1,\ldots,t_n)\)。工具覆盖率 TAO 为：

\[
\operatorname{TAO}=\frac{|\operatorname{Set}(t^*)\cap\operatorname{Set}(t)|}{|\operatorname{Set}(t^*)|}.
\]

TIO 根据与专家序列按顺序匹配的最长子序列长度 \(k^*\) 计算 \(k^*/m\)；TEM 根据从第一步开始完全一致的最长公共前缀长度 \(\ell_{\mathrm{lcp}}\) 计算 \(\ell_{\mathrm{lcp}}/m\)；Parameter Accuracy 除要求工具身份一致外，还要求其参数结构一致，并用满足这一条件的最长公共前缀长度除以 \(m\)。完整的数学集合表达见原文第 21 页公式 (3)–(6)。
